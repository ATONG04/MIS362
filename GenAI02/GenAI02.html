Before You Begin

Required computer and accounts

  • Windows 11, 64-bit, fully updated and restarted.
  • PowerShell 7.6 or newer. Use pwsh, not Windows PowerShell 5.1 or PowerShell ISE.
  • At least 16 GB RAM, a 512 GB SSD, and at least 25 GB free space.
  • Hardware virtualization enabled (Task Manager, CPU) and WSL 2 installed and current.
  • Docker Desktop installed and running with Settings > General > Choose how to run Docker containers  having  'WSL2' selected. Resolve prerequisite installation with the instructor or university support before class setup.
  • OneDrive - Minnesota State signed in and synchronized.
  • An OpenRouter account and an API key that can access the free router.
  • Student Hermes Starter Kit v2.0.7 supplied by the instructor.

WSL 2 requirement

WSL 2 supplies the real Linux kernel and lightweight virtualization layer used by the Docker Desktop Linux engine. Docker uses that layer to run the isolated Linux container used by Hermes terminal and code tools.

You do not need to install or open a separate Ubuntu distribution. PowerShell 7 and Hermes run on Windows. Docker supplies the isolated Linux Python, Node.js, and shell environment.

Quick prerequisite checks

Open PowerShell 7 and run:

$PSVersionTable.PSVersion
wsl --version
wsl --status
docker version
docker info --format '{{.OSType}}'
  • The PowerShell version must be 7.6 or newer.
  • wsl --version must report a WSL package version of 2.1.5 or newer. This is different from a distribution being configured as WSL 1 or WSL 2.
  • Docker Desktop must be open, docker version must reach the Docker server, and the final command must return linux.

If WSL 2 is missing or requires a Windows feature change, stop and follow the instructor or university-support procedure. Enabling WSL 2 can require Administrator approval and a restart; do not make unapproved system changes. If Docker Desktop has a first-run agreement or configuration screen, complete it and wait until the engine is running. Do not continue while a prerequisite is failing.

Step 3 — Configure the student values

The starter kit separates student-entered identifiers from instructor-managed settings:

  • StudentCourse_Config.psd1 contains only the five student values. This is the only configuration file students edit.
  • Course_Config.psd1 contains instructor-managed naming, source, Git workflow, inference, Docker, WSL, version, and security-related settings. Do not edit it.

Right-click StudentCourse_Config.psd1, choose Open with > Notepad, and edit only the quoted values. Save it with its existing .psd1 extension, not .psd1.txt.

For MIS362 it should contain:

@{
    # STUDENTS EDIT ONLY THESE FIVE VALUES
    CourseCode      = 'MIS362'
    StarID          = 'replaceWithYourStarID'
    NetworkUsername = 'replaceWithYourNetworkUsername'
    NetworkCourseID = '20273000022'
    GitHubUsername  = ''
}

Students are responsible for entering these five values correctly:

SettingMIS362 valueRule
CourseCodeMIS362Use the assigned course code. The starter kit derives the profile, workspace, shortcut, and backup names from it.
StarIDYour StarIDIt must exactly match the name of your Windows home folder.
NetworkUsernameYour ClassStorage/ network usernameThis is not your StarID or email address
NetworkCourseID20273000022Use the instructor-supplied course storage ID. Do not guess.
GitHubUsernameYour GitHub username or blankMIS362 currently has Git disabled for this Hermes workflow, so leave it blank. It becomes required only when the instructor-managed configuration enables Git.

This pattern lets you create a separate Hermes profile for another course: enter that course's code, your identifiers, the instructor-supplied network storage ID, and your GitHub username when that course uses Git.

The v2.0.7 scripts read both configuration files separately. The profile, workspace, backup, and OneDrive source use the lowercase course code plus hermes. The installed kit uses the uppercase course code plus _Student_Hermes_Starter_Kit. The configuration loader rejects extra student keys. This separation prevents accidental overrides; it is not a Windows file-permission restriction.

Never put a password, API key, token, or other secret in either PSD1 file. Keep the quotation marks, braces, and other PowerShell syntax exactly as supplied. Do not add keys or settings to StudentCourse_Config.psd1.

Security Boundaries and Stop Conditions

Why Docker isolation matters

An AI agent can propose and execute commands much faster than a person. A mistaken instruction, misunderstood path, unsafe package, or malicious text inside a file could otherwise affect unrelated course files, personal files, credentials, or network services. Docker reduces the impact of a mistake by placing Hermes terminal and code execution inside a short-lived Linux container with narrowly defined mounts, resource limits, and no terminal/code network connection.

Docker is one layer of defense, not a complete security guarantee. The Windows-side Hermes program still needs Internet access to call OpenRouter, and later browser tools may have their own separately controlled Internet access. Student judgment, approval prompts, protected credentials, and verification remain necessary.

What is and is not inside the Docker boundary

ItemDocker accessPurpose
Bounded course working copy/workspace/course, read/writeDocker terminal commands can edit the copied course files intended for the agent.
Git metadata or no-Git guard/workspace/course/.git, read-onlyBlocks writes to the mounted metadata/guard. Git-disabled mode is a workflow choice; it does not uninstall Git or prevent creating repositories elsewhere in the writable copy.
Course reference files/reference, read-onlyHermes may consult but not modify instructor-provided reference material.
Export folder/output, read/writeProvides a deliberate location for files that must leave the working copy.
OneDrive course sourceNot mountedThe synchronized authoritative source remains outside Docker; first setup copies it into the bounded working copy.
API key and profile .envNot mounted or forwardedThe kit does not forward the OpenRouter credential into the container environment. Never copy a credential into a mounted course file.
Other courses and Windows foldersNot mountedDesktop, Documents, Downloads, the broader Windows home folder, other profiles, and other course workspaces are outside the container's permitted file view.
Network backupsNot mountedClassStorage backups are created by the controlled Windows-side menu, not by agent terminal commands.

Expected security baseline

  • The terminal backend is Docker, and its current directory is /workspace/course.
  • Only the four approved host bind mounts listed above are configured; the container also has its own Linux image filesystem.
  • Docker terminal/code networking, Windows working-directory mounting, environment forwarding, and container persistence are off.
  • The configured container limit is two CPU cores and 4 GB RAM; persistence is disabled.
  • Persistent skill and memory writes require student approval.
  • GenAI02 does not ask you to add skills, tools, plugins, integrations, or model fallbacks. Hermes may include bundled capabilities; adding course-specific capabilities is later work.

Stop and contact the instructor if

  • The profile or workspace belongs to another course.
  • Setup cannot find the OneDrive course source folder.
  • Docker is not using its Linux engine.
  • The status check does not report Security settings: PASS.
  • A step asks you to run the course menu as Administrator, broadly change execution policy, disable antivirus protection, or weaken Docker isolation. Ask for help with any prerequisite installer that requests elevation.
  • A Hermes migration or compatibility check fails.

Do not delete profiles, reset the starter kit, change security settings, or run broad repair commands unless the instructor specifically directs you to do so.
